The RDF store (SPARQL)

Virtuoso, queried with SPARQL. It holds the same entities as the graph, expressed as RDF against the platform's own ontology, plus links out to Wikidata.

Prefixes

PREFIX f:    <http://data.fontem.eu/ontology#>
PREFIX wdt:  <http://www.wikidata.org/prop/direct/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

When to prefer it over Cypher

For chains of unknown depth. A property path such as f:subsidiaryOf* walks an ownership chain to its top in one expression, and FILTER NOT EXISTS then keeps only the ultimate parent. Expressing the same rollup in Cypher means a variable-length match and a good deal more care.

It is also the store to use when a query needs Wikidata properties — country of registration, industry classification — that live on the RDF side of the mirror.

SELECT ?parent (SUM(?value) AS ?totalEur) (COUNT(?contract) AS ?contracts)
WHERE {
  ?contract a f:Contract ;
            f:awardedBy ?authority ;
            f:awardedTo ?supplier ;
            f:valueEur ?value .
  ?authority wdt:P17 "DEU" .
  ?supplier f:subsidiaryOf* ?top .
  FILTER NOT EXISTS { ?top f:subsidiaryOf ?any }
  ?top rdfs:label ?parent .
}
GROUP BY ?parent
ORDER BY DESC(?totalEur)
LIMIT 20

Results come back as bindings and are flattened to columns and rows before a plot sees them, so a SPARQL source is used exactly like any other.
