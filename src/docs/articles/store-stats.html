The statistics warehouse (SQL)

PostgreSQL with TimescaleDB, queried with SQL. This is the store for regional statistics — Eurostat observations by NUTS region and time. Over 200 million rows.

The search path is fontem_stats, public, so table names need no schema prefix.

The three tables an analysis needs

observation

The measurements. One row per dataset, region, time and dimension combination.

  • dataset_code text — which dataset
  • geo_code text — NUTS region code
  • time timestamptz — the period
  • value double precision — the measurement
  • dimensions jsonb — the slice (sex, age, unit, …)
  • flags array — Eurostat quality flags

dataset

The catalogue. code, label, theme, source, source_url, nuts_levels, dim_ids, dim_labels (jsonb), time_unit, update_freq.

Query this first when you do not know a dataset code. Guessing codes wastes a round trip; they are not memorable.

nuts_region

code, level (0 country … 3 sub-region), name, name_native, parent_code, country_code, geometry, area_km2, nuts_version.

Filter by dimension, or you will double count

Most datasets are sliced. A crime dataset carries offence categories; a population dataset carries sex and age. Selecting without constraining dimensions sums every slice together, including totals that are themselves sums of the others. Check dataset.dim_ids and filter explicitly.

SELECT r.name AS region, o.value AS offences
FROM observation o
JOIN nuts_region r ON r.code = o.geo_code
WHERE o.dataset_code = 'crim_off_cat'
  AND r.level = 2
ORDER BY o.time DESC, o.value DESC
LIMIT 50

Coverage helpers

dataset_year_availability gives, per dataset and NUTS level, how many regions actually have a value in a given year. Use it before charting a time series: a line that drops to zero is usually missing data rather than a real fall. dataset_stats and dataset_slice_stats carry min/median/max ranges, useful for choosing sensible axis bounds.
