Adding a source query

A source is one query against one store. Choosing the store is the first decision, and the three are not interchangeable — each holds different data and speaks a different language.

LanguageStoreHolds
cypherNeo4j graph Companies, contracts, authorities, ownership, sanctions, lobbying
sqlStatistics warehouse Eurostat observations by region and year — 200M+ rows
sparqlVirtuoso RDF The same entities as RDF, for ontology and transitive queries

A rough rule: who did what with whom is the graph; how much, where, over time is the warehouse; chains of relationships to an unknown depth are RDF, where a property path does in one line what Cypher needs a variable-length match for.

Limits

Every source runs through a read-only proxy with a row cap and a timeout. Queries are for shaping a result set, not for exporting the database: filter and aggregate in the query rather than pulling rows to count them later. Query text is capped at 8000 characters.

What a source returns

All three engines return the same shape — a list of column names and a list of rows — so a plot does not need to know which store produced its input. SPARQL bindings are flattened to that shape automatically.

Run a source before building a plot on it. The column names it returns are what the plot's axes refer to, and they are not always what the query appears to name them.
