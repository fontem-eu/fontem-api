The browser transform (DuckDB)

A plot's transform step is DuckDB-WASM running inside the browser tab, over the rows the sources already returned. It is not a fourth data store and it has no connection to the databases.

What that means in practice

  • Always SQL. Whatever language produced a source — Cypher, SQL or SPARQL — it arrives here as a table. Writing Cypher in a transform produces a syntax error from an engine the author never chose.
  • Each source is a table named after the source, with the column names the source actually returned.
  • It cannot widen a result. The transform sees only the rows the sources fetched, already subject to their row caps. If a row was filtered out upstream, no join here will recover it.
  • It is free to change. Editing a transform re-runs it locally; it does not re-query anything.

What it is good for

Joining across stores — a Cypher source of contract counts against a SQL source of regional population, keyed on NUTS code. Pivoting long rows into the wide shape a chart wants. Aggregating a detailed source into the granularity you actually plot, so the source stays reusable for other plots.

SELECT c.region, c.contracts, p.value AS population,
       c.contracts * 100000.0 / p.value AS per_100k
FROM contracts_by_region c
JOIN population_by_region p ON p.geo_code = c.region
